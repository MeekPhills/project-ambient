# Decision records

Decision records capture accepted product, architecture, privacy, licensing, and support boundaries that affect more than one implementation issue.

- **Accepted** records are binding until a later record supersedes them.
- **Proposed** records do not authorize implementation.
- A change that affects user data, licensing, platform claims, or the canonical readiness tracker requires an explicit record rather than an undocumented code choice.
